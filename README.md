# 두리 · 마을 키우기 웹 프로토타입

작업 위치: `/home/soohyun/newduri`

서버 없이 `index.html`을 브라우저에서 직접 열어 사용할 수 있습니다. 패키지 설치는 필요하지 않습니다. 외부 글꼴을 불러오지 못하면 시스템 글꼴을 사용합니다. 최신 캐릭터 해금·배치와 환경 변화 규칙은 `FEATURES.md`에 정리했습니다.

## 화면과 조작

- 상단 메뉴는 지도와 수집함 두 개입니다. 감성적인 소개 문구를 제거했습니다.
- 지도 표식이나 도시 이름을 클릭하면 즉시 마을로 입장합니다. 도의 표식은 선택 중인 도시 또는 해당 도의 첫 번째 도시로 이동합니다.
- 오른쪽 마을 정보와 실험실은 마을 안에서만 표시합니다. 다섯 카테고리의 공유 수를 +/−로 조절합니다.
- ‘모두 3단계로’ 버튼으로 완성된 마을과 무지개 아치를 시연합니다.
- 마을에서는 방향키, WASD, 화면의 네 방향 버튼 또는 도로 클릭으로 이동합니다.
- 20/30 FPS 선택, 이용 안내, 도시별 통계와 가상 장소 목록을 제공합니다.
- 수집함에서 배지·트로피·아치와 캐릭터를 확인하고, 배치할 마을을 선택해 캐릭터를 클릭하여 배치·해제합니다.
- 장소 목록의 공유·방문 버튼은 모의 이벤트입니다. 실제 방문 인증이나 외부 공유 연동은 아닙니다.
- 계절과 이벤트를 선택하거나 한국 날짜로 자동 적용합니다. 우세한 건물 카테고리도 환경에 반영합니다.
- ‘이 도시 초기화’는 확인 후 해당 도시의 공유 수와 보상만 초기화합니다.
- 모바일에서는 실험실이 마을 아래에 배치됩니다.

## 게임 규칙

식당·놀거리·자연·카페·랜드마크 다섯 건물은 모두 1단계에서 시작합니다.

| 공유 수 | 건물 |
| --- | --- |
| 0–2회 | 1단계 |
| 3–6회 | 2단계, 배지 획득 |
| 7회 이상 | 3단계, 트로피 획득 |

카테고리별 공유 수 범위는 0–99입니다. 감소하면 건물도 낮아지지만 획득 보상은 유지합니다. 다섯 건물이 모두 3단계에 도달하면 무지개 아치를 얻습니다. 도시당 보상은 11개이며 금전적 가치가 없습니다.

도시별 기록과 프레임 설정을 localStorage에 저장합니다. file://에서 저장을 차단하는 브라우저에서는 경고를 표시하고 메모리에서 계속 실행합니다.

## 캐릭터와 도로

두리는 첨부 원화의 흰 얼굴, 회색 몸, 짙은 귀, 파란 스카프를 단순화한 SVG 캐릭터입니다. 고양이 두 마리와 비버 한 마리가 자동으로 산책합니다.

- 30°, 150°, 210°, 330°의 네 방향을 구분합니다.
- 걷기는 기본 20 FPS이며 30 FPS로 변경할 수 있습니다. 프레임 사이를 보간하지 않습니다.
- W/↑: 30°, A/←: 150°, S/↓: 210°, D/→: 330°.
- 보조 키 Q/E/Z/C: 화면의 ↖/↗/↙/↘.
- x 또는 y가 0, 3, 6인 도로망만 이동합니다.
- 도로 클릭 시 BFS로 경로를 찾습니다. 건물 부지를 가로지르지 않습니다.
- 이동 중 목적지를 바꾸면 현재 구간을 마친 뒤 새 경로를 따릅니다.

## Mock 데이터와 앱 통합

이전 두리 앱과 분리된 오락 요소 프로토타입입니다. 실제 공유 수신, 계정, 커플 연결, 장소 저장, 지도 API는 구현하지 않습니다.

- 17개 시·도 그룹 아래 시 단위 85개 지역.
- 각 도시의 가상 장소 10개, 카테고리당 2개, 총 850개.
- 모든 장소는 `isMock: true`이며 실제 영업 장소를 표현하지 않습니다.
- 지도는 지역 선택용 개념도입니다. 좌표는 그림 좌표이며 위도·경도가 아닙니다.
- 공유 수는 고유 장소 수와 별개인 가상 이벤트 횟수이므로 카테고리별 장소가 2개여도 7회 이상을 시연할 수 있습니다.

`data.js`의 `createMockPlaceRepository()`를 다음 계약의 API adapter로 교체할 수 있습니다.

```js
// Region = { id, name, x, y, cities: City[] }
// City = { id, name, regionId }
// Place = { id, cityId, categoryId, name, isMock }
// categoryId = food | play | nature | cafe | landmark
const repository = {
  listRegions() { /* Region[] */ },
  listCities(regionId) { /* City[] */ },
  async listPlaces(cityId) { /* Place[] */ }
};
```

실제 공유 이벤트를 cityId와 categoryId에 매핑하여 `DuriModel.changeCount(cityState, categoryId, delta)`에 전달합니다. 서버 저장·인증·이벤트 중복 제거는 호스트 앱에서 담당합니다. 장소명은 textContent로 출력합니다.

## 구조

- `index.html`: 지도·마을·수집함·실험실 UI.
- `style.css`: 파스텔 스타일과 반응형 레이아웃.
- `data.js`: 교체 가능한 mock 장소 repository.
- `model.js`: 성장·보상·저장 검증·도로·경로·좌표 변환.
- `art.js`: 마을과 캐릭터 SVG.
- `app.js`: UI 연결, 이동, 저장, 프레임 설정.
- `features.js`: 캐릭터 해금·배치·장소 이벤트·계절·이벤트·카테고리별 환경.
- `features.css`: 마을 전용 우측 패널과 캐릭터 수집 UI.
- `tests/`: 규칙 및 UI 이벤트 흐름 검사.
- `server.mjs`: 선택적 로컬 서버. 실행하지 않아도 됩니다.

## 검증

개발 환경에서 `npm test`와 `npm run check`를 실행할 수 있습니다. 이번 환경에서는 쉘 오류 때문에 로컬 명령과 실제 브라우저 화면 검사는 수행하지 못했습니다. 별도 JavaScript 실행기에서 핵심 규칙·경로·구문 및 DOM 대역을 이용한 UI 흐름을 검사했습니다. 상세 내용은 `VERIFICATION.md`에 기록했습니다.
